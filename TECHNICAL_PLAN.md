# Технічний план

1. **Контракт API.** Використовувати лише актуальні read-only методи офіційного Checkbox API: вхід касира, пошук чеків, отримання PNG. Не викликати endpoints створення чеків, змін або повернень.
2. **Безпека.** Логін зберігати у локальних налаштуваннях, пароль — окремо, зашифрований Windows DPAPI для поточного користувача. JWT тримати лише в пам'яті та автоматично перевходити після `401/403`.
3. **Дані.** Завантажувати `/api/v1/receipts/search` сторінками по 100 записів через `limit/offset`, доки сторінка не стане неповною. Дати передавати як ISO-8601 із локальним часовим поясом.
4. **Інтерфейс.** WPF + власний невеликий MVVM-шар без сторонніх framework-ів. Українські фільтри, таблиця, пошук, вибір, preview, налаштування й діагностика.
5. **Друк.** Завантажувати офіційний PNG, перевіряти `PrintCapabilities`, валідований `PrintTicket`, фактичну imageable area та формат, масштабувати пропорційно і за замовчуванням створювати окремий Windows print job для кожного чека.
6. **Надійність.** Виконувати XPS/PrintQueue роботу на окремому STA worker, фіксувати унікальний Windows job ID, не прирівнювати spooler-status до фізичного друку, підтримувати зупинку подальших submit-операцій і безпечний повтор лише pre-submit помилок.
7. **Перевірка.** Mock HTTP-тести парсингу, пагінації, дат, retry/error handling; unit-тести snapshot вибору, сортування, прихованих чеків, скасування, retry policy, геометрії та драйверних обмежень; Release publish `win-x64` self-contained single-file і portable ZIP.

Перевірена 21.09.2026 офіційна OpenAPI-специфікація: `checkbox API 2.107.0+7e00a4c6`.
