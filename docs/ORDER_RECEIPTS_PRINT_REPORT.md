# Чеки вибраних замовлень і кнопки над таблицями — 1.0.70

«Повторити невдалі» та «Друк вибраних видимих» перенесені з нижньої панелі над кожною таблицею чеків. Вони використовують наявні команди активної вкладки, її видимі рядки та окремі позначки. Нижня панель накладних збережена.

Поряд із «Друк наклейок і чеків» додано «Друк чеків замовлень». Вона фіксує позначені видимі замовлення в поточному порядку їхньої таблиці. Усі завантажені пов’язані чеки одного замовлення йдуть разом, за датою, числовим номером та ID. Пошук, тип, сортування та галочки таблиць чеків не змінюють цей набір. Приховані позначені замовлення не друкуються, їх кількість показується у підтвердженні.

ТТН, ключі доставки, налаштування чи принтер наклейок для цієї дії не потрібні. Наявна історія й статуси наклейок не змінюються. Галочки замовлень і двох таблиць чеків зберігаються, щоб можна було надрукувати наклейки окремо.

Перед передаванням перевіряється весь набір: немає скасованих замовлень, відсутніх або неготових чеків, повторення того самого ID між вибраними замовленнями; максимум 250 чеків і 80 МіБ PNG. Завантажуються всі зображення й перевіряється макет. Якщо одна частина недоступна, частковий пакет не надсилається. Після підтвердження повторно перевіряються обліковий запис, контекст підключень, зв’язки, метадані чеків і доступність зафіксованого принтера.

Раніше передані чеки та невизначений результат попередньої спроби показуються у підтвердженні; для повтору потрібна окрема галочка. Ця перевірка спільна зі звичайним друком вибраних чеків і повтором невдалих, тому перемикання способу друку не обходить попередження. Це звичайна історія друку чеків. Помилка збереження історії не змінює успішний результат передавання та не запускає повтор. Під час операції блокуються паралельний друк, новий вибір прив’язки та зміни пакета; сортування чи перемикання вкладки не перебудовують уже підтверджену послідовність.

Перевірки використовують штучні PNG, сховища та принтери: порядок кількох чеків на замовлення, відсутні налаштування наклейок і ТТН, незалежні галочки й фільтри, приховані замовлення, скасування, застарілий зв’язок, зміна касира чи чека, помилка підготовки/передавання/історії, повторний друк та конкурентні команди. Скомпільований XAML перевіряє розміщення й прив’язки кнопок. Реальні API й фізичний друк у цих перевірках не використовуються.
