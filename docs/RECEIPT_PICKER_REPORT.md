# Ручний вибір чека із замовлення — 1.0.67

У таблиці замовлень кнопка «Прив’язати» займає місце відсутньої кнопки чека. Наявні точні, ручні та ймовірні зв’язки зберігають свої кнопки перегляду; ручний зв’язок із чеком поза завантаженим списком також вважається наявним.

Вікно показує вільні завантажені чеки незалежно від пошуку та фільтрів основних таблиць. Є дата й час за Києвом, сума, перегляд офіційного PNG, номер чека, фіскальний номер, тип і повний UUID. Фільтри «Дата від / до» включають увесь календарний день; обидві межі можна очистити. Пошук знаходить частину UUID, фіскальний або серійний номер без урахування регістру, а суму порівнює точно до копійок з підтримкою крапки, коми й розділювачів тисяч. Невідомі суми не перетворюються на нуль.

Чеки, зайняті іншим точним, ручним чи ймовірним зв’язком, не пропонуються. Збережене ручне рішення резервує чек навіть тоді, коли відповідне замовлення зараз не завантажене. Пошук і календар не роблять нових API-запитів; для іншого періоду спочатку потрібно завантажити чеки в головному вікні.

«Прив’язати чек» підтверджує локальне ручне рішення через наявне захищене сховище. Скасування, пошук і перегляд не змінюють прив’язок або позначок друку. Перед записом повторно перевіряються обліковий запис, контекст, моделі документів і доступність чека: фонове оновлення під час модального вікна не дозволяє прийняти застарілий вибір. Новий вибір і перегляд не обходять блокування основної операції друку.

В обох таблицях чеків окремі «Дата» та «Час» замінено колонкою «Дата й час» у форматі `dd.MM.yyyy HH:mm:ss`. Сортування використовує значення дати, а не текст. Кнопка «Перегляд» стоїть одразу після жирної суми та зберігає команду перегляду конкретного чека.

Автоматичні перевірки охоплюють ручне підтвердження й скасування, відновлення після перезапуску, чужі та позадіапазонні зв’язки, застарілий вибір, незалежні фільтри, формати сум, межі дат Києва, зайнятість друку, помилку перегляду та скомпільовані XAML-прив’язки. Знімки інтерфейсу створюються лише на синтетичних даних; справжні API та фізичний друк для цих перевірок не використовуються.
