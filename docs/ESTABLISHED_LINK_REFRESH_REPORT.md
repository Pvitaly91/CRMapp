# Готові прив’язки під час оновлення — 1.0.62

Під час «Оновити все» свіжість даних Checkbox тимчасово скидається. Попередня реалізація застосовувала неповне покриття до всіх пар: точний зв’язок перетворювався на `Incomplete` без замовлення, а після перевірки API з’являвся знову. Кеш імовірних пар Prom уже підтримував окремі збережені зв’язки, але точні фіскальні пари залежали від повного знімка графа, який змінюється при додаванні нового чека.

Оновлення тепер зберігає готові пари в інтерфейсі від самого початку паралельних запитів. Уже прийнята точна фіскальна пара повторно використовується в пам’яті поточного облікового сеансу; повторний API-пошук для неї не потрібний. Нові чеки й незв’язані замовлення обробляються окремо та не отримують готового статусу лише через існування старих пар.

Повторне використання стосується тієї самої пари Receipt UUID / OrderKey у тому самому обліковому контексті. Перевіряються незмінні фіскальні твердження, дані чека, налаштування підключень, поточні ручні рішення та колізії серед завантажених документів. Оновлення трекінгу, статусу чи товарів замовлення саме по собі не змінює точне фіскальне посилання. Зміна касира, відхилення або переприв’язка вручну, зміна фіскального документа й суперечливі посилання потребують нової перевірки.

Доказ авторизованого пошуку не записується в кеш замовлень чи ручні рішення. Після перезапуску його перевіряє звичайний процес першого завантаження. Збережені імовірні пари Prom продовжують використовувати наявний захищений кеш.

Автоматичні перевірки охоплюють паралельне оновлення з новим чеком і затриманим API, відсутність проміжного зникнення готових пар, виключення вже зв’язаних документів із повторних запитів, неповний або скасований запит, нові суперечності та зміну облікового контексту. Фізичний друк для цих перевірок не потрібний.

Повний локальний набір пройшов **664/664** перевірки. Сценарії повторного оновлення рахують виклики самого verifier і HTTP окремо, щоб кеш HTTP не приховав зайву повторну перевірку. Для вже зв’язаних чеків не було нових викликів verifier або завантажень товарів; для нового документа Rozetka виконувався лише його власний пошук.
