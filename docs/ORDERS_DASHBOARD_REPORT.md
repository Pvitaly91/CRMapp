# Компактна таблиця замовлень — 06.10.2026

Версія 1.0.25 прибирає з лівої таблиці колонки «Маркетплейс», «Зв’язок із чеками», «Пов’язані чеки» та «Доставка». Номери чеків і кнопки відкриття залишаються в колонці «Відкрити чек». Незалежна інфоіконка доступна також для незв’язаних замовлень і показує маркетплейс, попередній статус зв’язку, список пов’язаних чеків (включно зі збереженими поза діапазоном) та повне пояснення. Наведення або натискання відкриває інформацію. Дані й колонки правої таблиці чеків не змінені.

Prom використовує світло-синій `#EDF5FF`, а після передавання всіх поточних ТТН — `#BFDAFA`. Для Rozetka це `#EFFAF2` та `#BCE8C9`. Джерело сильного відтінку — чинний `HasPrintedLabel` із журналу наклейок; друк пов’язаного чека не змінює цей стан. Він відновлюється після перезапуску та змінюється після заміни ТТН. Статус передавання Windows не підтверджує фізичного виходу паперу.

Номер біля checkbox — `DisplayIndex`, від 1 у поточному `Marketplace.Orders`. Зміна фільтра чи сортування перенумеровує видимі рядки. При завантаженні набору замовлень перерахунок виконується один раз наприкінці, а не для кожного вставленого запису. Галочки лишаються прив’язаними до моделі замовлення; номер не зберігається в кеші/API.

Перевірено справжній скомпільований XAML на 48 синтетичних Prom/Rozetka замовленнях: чотири відтінки, кілька послідовних надрукованих рядків, зміна історії/сортування, linked/unlinked info, параметри PreviewCommand, checkbox, фільтри, сортування, нумерація після прокручування та повторного використання контейнерів. Старі XAML-очікування оновлені для нових палітр і переміщених пояснень. PNG нового вигляду збережено та візуально перевірено.

Повний набір: 368/368 тестів, exit code 0. Реальні API та принтери під час перевірок не викликалися; налаштування, ручні зв’язки та історія не змінювалися.
