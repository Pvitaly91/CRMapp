# Кнопки вибору замовлень під час фонового оновлення — 1.0.43

Галочка масового вибору та іконка кандидатів перевіряли загальне `MarketplaceWorkspaceViewModel.IsBusy`. Цей стан триває протягом синхронізації маркетплейсів, завантаження деталей чеків і збереження кешу, тому при звичайному фоновому оновленні вже видимі замовлення залишалися недоступними для вибору. Окремі галочки рядків і таблиця чеків працювали за іншими умовами.

Два селектори більше не блокуються загальною зайнятістю маркетплейсів. Власна операція наклейок, явне «Оновити все» та знищення моделі продовжують блокувати ці команди. Іконка кандидатів читає локальну історію й застосовує вибір до поточних видимих рядків. Перевірка покоління контексту після читання не дає запізнілій операції змінити вибір іншого акаунта, дат або конфігурації. Вибір не звертається до API й не друкує.

Правила кандидатів, галочка всіх рядків, приховані позначки, перевірка історії та збереження галочок при оновленні тих самих ключів замовлень залишаються. Перед передаванням наклейок Windows, як і раніше, перевіряється актуальність замовлень і ТТН.

Додано три регресії з призупиненим фоновим API й локальним читанням історії: вибір/зняття та збереження галочок після оновлення; застосування історії до актуальних рядків і нових ТТН зі збереженням прихованих галочок; відхилення запізнілого читання після зміни контексту. Скомпільований XAML перевіряє натискання обох кнопок під час фонового запиту, а також їхнє блокування під час «Оновити все». Перевірка блокування під час друку залишилася. Повний набір: **499/499**. Сценарії використовують вигадані дані без справжнього API й фізичного друку.
