# Спільний календар і кеш автоприв’язок

Дата: 27.09.2026. База: `320d4c1c05b743f6c007e11b3e92a540019931ef`, гілка `codex/checkbox-marketplace-orders`. Перед змінами робоче дерево чисте.

## Поведінка інтерфейсу

- «Дата від / Дата до» одразу застосовуються до обох вкладок чеків і таблиці замовлень, у часовому поясі Києва. Порожня межа не обмежує відповідний бік; перевернутий діапазон показує порожній список. Невідома дата не проходить задану межу.
- Це фільтр уже завантажених даних, без запиту API на кожне редагування календаря. Для отримання ще не завантаженого періоду потрібне «Оновити чеки» / «Оновити замовлення»; «Сьогодні» завантажує чеки, як раніше.
- Джерельні колекції, приховані галочки та повна область зіставлення збережені. Фільтр не робить пару унікальною через приховування конкурента. Без облікового запису Checkbox зміна дат також не очищає локальний список замовлень, але змінює межі наступного запиту.
- Наявну кнопку зіставлення перейменовано на «Оновити автоприв’язки». Вона оновлює замовлення, перевіряє зв’язки для завантажених чеків і працює також після неповної перевірки. Збережені ручні рішення, відхилення та точні фіскальні зв’язки мають пріоритет.

## Кеш і коректність

Файл development-профілю: `%LOCALAPPDATA%\CheckboxBatchPrinter\Marketplaces\automatic-matches.dpapi`. Розташований поза EXE, тому заміна/оновлення development-збірки його не видаляє. Це окреме DPAPI-сховище для поточного Windows-користувача, а не ручні прив’язки та не історія друку.

Зберігаються ключі документів, перевірені результати зіставлення, пояснення, товарні деталі чеків і хеші вхідних даних. Паролі, токени, PNG та контакти/дані покупців не дублюються у цей кеш. Строк — налаштовані 1–90 днів (30 за замовчуванням), без подовження від одного читання. Є обмеження кількості контекстів, деталей, знімків і розміру файла. Ключ включає обліковий контекст касира; ключ замовлення включає маркетплейс і постійний ID підключення.

Після перезапуску відновлюються лише результати незміненого повного набору даних із попередньою повною перевіркою того самого діапазону всіх увімкнених підключень. Пояснення позначає, що це збережений результат, який очікує оновлення API. Неповний або змінений набір не отримує новий автозв’язок на підставі старого кешу.

Повторні мережеві запити товарних деталей незмінених чеків усуваються: їх читаємо з кешу після перевірки fingerprint. Нові, змінені або прострочені деталі запитуються за потреби, максимум 100 за операцію. Результат незміненого графа повторно використовується. Якщо документи змінилися, локально перераховується весь граф, а не лише вільні рядки: ймовірні зв’язки не резервують замовлення та не ховають нових конкурентів. Це необхідна перевірка, а не повторне завантаження всіх деталей.

Fingerprint враховує вхідні чеки, замовлення, ручні рішення, деталі, область і версію алгоритму; підтверджені в пам’яті фіскальні дані враховуються окремо від `JsonIgnore`. Час повторного отримання того самого замовлення сам по собі не інвалідує результат. Пошук та видимі фільтри не входять у ключ.

Пошкоджений/прострочений кеш відновлюється повторною перевіркою. Помилки його збереження не блокують поточне зіставлення чи базову вкладку чеків. Асинхронне збереження очікується, має захоплений обліковий контекст, перевірку покоління й ізольоване файлове блокування.

## Виконані перевірки

- Release-збірка рішення.
- 178/178 синтетичних тестів, включно з попередніми регресіями та Windows/STA compiled-XAML тестом назви/прив’язки кнопки.
- Нові STA-сценарії: обидві таблиці одразу реагують на дату; київська північ, відкриті межі; збереження прихованого конкурента і галочок; перезапуск із кешем; кнопка запитує деталі лише нового чека; новий конкурент скасовує стару ймовірну пару; змінений чек із тим самим ID запитується заново; ручні рішення та неповне нове підключення не обходяться кешем; помилки I/O не блокують роботу.
- Нові core-сценарії: реальний локальний DPAPI round-trip на синтетичних даних, розділення облікових контекстів, перестановки вхідних списків, зміна графа/області/фіскального підтвердження, TTL/версія/межі кешу, пошкоджений binary та зашифрований некоректний JSON.
- Перший інтеграційний прогін: 170/171. Старий тест точного фіскального зв’язку містив чек 24.09 при календарі тільки 23.09. Його діапазон розширено до фактичних дат сценарію; перевірки точного зв’язку й ізоляції друку збережені.

Команди відтворення:

```powershell
dotnet build CheckboxBatchPrinter.sln -c Release --artifacts-path artifacts/auto-cache-check
& .\artifacts\auto-cache-check\bin\CheckboxBatchPrinter.Tests\release\CheckboxBatchPrinter.Tests.exe
$sourceRevision = (git rev-parse HEAD).Trim()
dotnet publish src/CheckboxBatchPrinter/CheckboxBatchPrinter.csproj -c Release -r win-x64 --self-contained true -p:AppChannel=Development "-p:SourceRevisionId=$sourceRevision" --artifacts-path artifacts/auto-cache-publish -o artifacts/development/cached-auto-links-1.0.2
```

## Межі перевірки та production

Не виконували реальних API-запитів, фіскальних операцій або фізичного друку. Відновлення саме реальних користувацьких прив’язок потрібно перевірити запуском нового development EXE, оновленням і повторним відкриттям. До першого успішного оновлення старий білд не міг створити новий файл автокешу.

Production EXE 1.0.1 і production-профіль не змінено. Контрольний SHA256 production EXE: `9E7F1C6675BBF6409092B6FBD817D400908B2C907E7EA676AE47F435D69B0F80`. Новий self-contained win-x64 білд розміщується тільки в `artifacts/development/cached-auto-links-1.0.2`; переносити потрібно всю папку. Секрети, користувацькі кеші й покупці не додаються до Git.
