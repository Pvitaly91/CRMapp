# Скасовані замовлення не беруть участі в автозіставленні — 06.10.2026

Версія 1.0.23 виключає замовлення з явним статусом скасування з товарного графа, сумових кандидатів та запитів товарних деталей. Скасований запис залишається в кеші й таблиці замовлень. Підтверджені вручну та точні фіскальні зв’язки зберігаються, зокрема для історичних чеків.

Спільна ознака `MarketplaceOrder.IsCanceled` читає `SourceStatus` і `Status`, прибирає крайні пробіли та порівнює без регістру точні значення `canceled`/`cancelled` і локалізовані назви скасування. Статус оплати, невідомі числові коди та рядки на кшталт `cancel_pending` не використовуються для такого виключення.

Збережений Suggested видаляється, якщо актуальне замовлення стало скасованим. Це окрема перевірка: відбиток власної пари не змінюється від звичайних змін статусу. Зовнішні/відновлені Suggested також перевіряють актуальний запис замовлення. Граф v11 замінює старі кешовані результати; вручну збережені рішення та незмінені автозв’язки активних замовлень залишаються.

Випадок із локального кешу: чек 4669 від 05.10 о 21:51 має 1 ремкомплект Honda за 400 грн і NovaPay. Замовлення 431797758 від 21:22 узгоджується з ним, але скасоване замовлення 431604463 від 06:22 з таким самим кошиком також залишалося конкурентом. Новий алгоритм виключає 431604463 і знаходить 431797758 ↔ 4669. Перевірка відбувалася лише в пам’яті, без API, друку чи зміни файлів профілю; контрольні суми вхідних файлів незмінні.

До виправлення три нові регресії падали: 360/363 тестів. Перевірки охоплюють конкретного скасованого конкурента, локалізовані й сирі статуси Prom/Rozetka, невідомі статуси/неповні документи, скасування після збереженого автозв’язку, часткове оновлення, перезапуск та пріоритет ручних/фіскальних прив’язок. STA-перевірка проходить через обидві таблиці: скасоване замовлення лишається видимим, його товари не спричиняють запиту чека, додане активне замовлення отримує автозв’язок і відновлюється після перезапуску.

Після виправлення та додавання STA-сценарію: 364/364 тестів, exit code 0. Фізичного друку та звернення до реальних API під час тестів немає.
