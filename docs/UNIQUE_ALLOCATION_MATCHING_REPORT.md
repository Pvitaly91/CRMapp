# Єдиний розподіл вільних чеків і замовлень — 03.10.2026

Версія 1.0.22 виправляє нерозподілені групи, які 1.0.21 залишала неоднозначними навіть за наявності єдиного можливого зіставлення. Правило «замовлення створено не пізніше чека того самого дня за Києвом» уже виключало пізнє замовлення для раннього чека, але граф вимагав унікальності кожної пари в обох напрямках до резервування будь-якої з них.

Новий алгоритм працює тільки з вільними документами. Для групи з однаковою кількістю чеків і замовлень та повними узгодженими кошиками він послідовно резервує вимушену пару: чек із єдиним доступним замовленням. Результат застосовується лише якщо так розподілено всю групу. Цикли, нестача документів, невідомі суми/дати/валюта/товари, коригування, неперевірені фіскальні дані та ручні відхилення/вимкнення блокують цей висновок. Для оплат залишається попереднє правило взаємно унікальної пари; новий розподіл не виводить додаткові пари через виключення за оплатою.

Це автоматичний ймовірний зв’язок за сумою й товарами; ручні рішення та фіскальні ключі мають пріоритет. Знайдені пари зберігаються в наявному кеші. Граф v10 замінює результати v9; збережені пари та рішення залишаються.

Збережено всі 153 попередні пари та додано чотири нові. Контрольні суми вхідних файлів профілю після аудиту незмінні.

Нові перевірки охоплюють порожній кеш, зворотний порядок API, довгі ланцюги, перезапуск, неоднозначні цикли, неможливий повний розподіл, неповні/невідомі дані та ручні пріоритети. STA-сценарій проходить через обидві таблиці, перевіряє відсутність ручного збереження та повторного читання товарів після призначення.

До виправлення новий сценарій відтворив проблему: 357/358 тестів, падіння саме початкового розподілу ранкового й вечірнього продажів. Після виправлення та додавання STA-сценарію: 359/359 тестів. Фізичного друку та змін у реальному профілі під час тестів немає.
