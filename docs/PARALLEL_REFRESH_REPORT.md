# Паралельне оновлення — 1.0.45

Раніше «Оновити все» чекало завершення Checkbox перед запитами маркетплейсів, а потім завантажувало накладні. Prom і Rozetka також обходилися послідовно. Тепер завантаження цих чотирьох служб починається в одному циклі без очікування відповідей інших API. Rozetka Delivery читається окремо від Нової пошти. Той самий порядок застосовано до фонового циклу.

Кожен сервіс зберігає послідовний обхід своїх акаунтів, сторінок і деталей. Запис спільного кешу маркетплейсів серіалізований, щоб паралельні результати не втрачали замовлення іншої служби. Завершені підключення зберігаються навіть при помилці або скасуванні іншого потоку.

Результат замовлень спочатку залишається приватним до завершення запиту Checkbox. Після цього застосовуються точні UUID-прив’язки й перевірки товарів. Старе фонове завантаження чеків не замінює явне «Оновити все» й не підтверджує свіжість нового циклу. Зміна дат, касира або налаштувань відхиляє пізню відповідь. Перед застосуванням рядків очікується завершення фактичної операції друку наклейок; читання історії для вибору кандидатів цього очікування не потребує.

Фонове завантаження накладних використовує поточний період відображення. Стан доступних перевізників перевіряється окремо: неналаштований Delivery не робить успішне завантаження Нової пошти помилкою. Серверні паузи, повтори після помилок та заборона повторної авторизації без перевірки облікових даних збережені.

Регресійні перевірки використовують керовані затримки й підроблені API та принтер. Вони перевіряють одночасний старт усіх служб, незалежні помилки, послідовний обхід сторінок, серіалізовані записи кешу, скасування, зміну контексту, пізній UUID/товари, старий фоновий запит та захист рядків під час друку. Фізичний друк і зміни в зовнішніх сервісах для цих перевірок не виконуються.

Повний набір — 525 тестів, включно з компільованими XAML та перевірками попередніх можливостей. Стандартний `Build-Production.ps1` повторює цей набір для Development і Production та перевіряє запуск окремої копії однофайлового EXE, його перезапуск, профілі й native PDF-компонент.

Паралельність прибирає сумування часу незалежних API. Фіксованого прискорення немає: цикл усе ще очікує найповільнішу службу та необхідні деталі для точного зіставлення. Джерела, тести та стандартні скрипти збірки зберігаються в GitHub; тимчасові результати збірки для відновлення не потрібні.
