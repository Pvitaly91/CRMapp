# Збереження підключень Rozetka — 1.0.40

Порожні поля після повторного відкриття раніше виглядали як втрата даних: логін теж очищався, хоча він зберігався в захищеному файлі разом із паролем. Тепер вибране підключення показує збережений логін та індикатор «Збережено». Пароль і токен із файлу не підставляються в поля. Введені, але ще не записані чернетки залишаються в пам’яті цього вікна й відновлюються при перемиканні магазинів.

Саме відображення збереженого логіна не створює чернетки й не перезаписує секрет. Пізнє асинхронне читання іншого підключення або стану до нового збереження не змінює актуальні поля. `CredentialFieldsChanged` синхронізує масковані `PasswordBox` з поточною чернеткою; обробник очищення більше не стирає відновлену чернетку при перемиканні.

Збереження фіксує копії підключень і чернеток. Усі назви та повні пари Rozetka перевіряються до першого запису секрету; новий пароль без логіна та новий логін без пароля відхиляються. Зміна логіна на інший акаунт у наявному ID підключення, як і раніше, вимагає нового підключення. Під час запису редагування та повторний Save заблоковані.

Основні й маркетплейсні налаштування записуються до застосування фонового режиму й автозапуску. Якщо їх застосування не вдається, повідомлення прямо вказує, що дані вже збережені. Закриття такого вікна залишає ознаку записаних змін, щоб основний екран перечитав конфігурацію.

У фоновому керованому режимі новий магазин міг залишатися в кешованій конфігурації до перезапуску. Після збереження `InvalidateConfiguration()` скасовує старі операції, змінює покоління й змушує наступне локальне приєднання перечитати підключення. Акаунт, чеки, замовлення, поточні галочки, ручні прив’язки та історія друку залишаються. Запізніла відповідь попереднього покоління не застосовується.

Додано 9 регресій на тимчасових JSON/DPAPI-сховищах із вигаданими даними: Save/reopen, чернетки магазинів, неповні пари без часткового запису, пізнє читання, відсутність зайвих записів, помилка фонового callback після збереження, конкурентні Save та застосування нового магазину без перезапуску. Скомпільований SettingsWindow перевіряється через реальні поля, перемикання підключення, Save й повторне відкриття; індикатор та порожній збережений пароль перевірені в рендері. Повний набір: **475/475**. Справжні ключі не використовуються в тестах; HTTP й фізичний друк не запускаються новими сценаріями.
