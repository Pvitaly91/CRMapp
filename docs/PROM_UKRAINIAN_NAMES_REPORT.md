# Українські назви товарів Prom для зіставлення з Checkbox

27.09.2026. База `d19b4a32dd2fea3cd1baaf8ed5aed043d82ec995`, development-гілка `codex/checkbox-marketplace-orders`. HEAD і чистий git status перевірені до змін.

## Причина та виправлення

Адаптер надсилав `X-LANGUAGE: uk`, але читав лише `products[].name`. Реальне API повернуло в цьому полі російські назви, одночасно надавши українські в `products[].name_multilang.uk`. Обидва поля описані в офіційних схемах [товару замовлення](https://public-api.docs.prom.ua/documentation/Orders/schemas/Product.yaml) та [перекладів назви](https://public-api.docs.prom.ua/documentation/common/schemas/ProductNameMultilang.yaml), повторно прочитаних 27.09.2026.

У спільному parser списку й деталей замовлення тепер першою вибирається непорожня строка `name_multilang.uk`. Вона стає назвою позиції для UI, кешу та зіставлення з Checkbox. Правило працює для **всіх товарів Prom**, незалежно від назви, типу, ID чи ціни. Окремих GET каталогу товарів не потрібно; список дозволених endpoint і права API не розширювалися.

Якщо українське значення відсутнє, порожнє або має неправильний JSON-тип, залишається вихідна `name`. Інші мови чи недокументовані ключі не вгадуються; відсутня назва не замінюється вигаданою. Змінено лише вибір назви: кількість, SKU, ціни, суми, повнота кошика, правила сум/дат/унікальності, ручні й фіскальні пріоритети збережені. Алгоритм не перекладає назви самостійно та не знімає неоднозначність дублів однакових замовлень.

## До / після та тести

Спершу додано API-регресію для списку й деталей із російською `name` та іншою українською `name_multilang.uk`. Використано довільні товари поза словником типів попередньої зміни.

- До виправлення: новий тест упав з `Ukrainian name_multilang.uk was ignored`; **191/192** пройшли.
- Після: **195/195** пройшли, Release — **0 помилок і 0 попереджень**.
- Перевага українського поля в обох методах; довільні назви, відсутня вихідна назва, обрізання крайніх пробілів; гроші/кількість/повнота незмінні, додаткових API-запитів немає.
- Відсутні/порожні/числові/булеві/масивні/об’єктні значення та неправильний ключ локалі зберігають вихідну назву без помилкових перекладів.
- Реальний Prom parser → реальний Checkbox detail parser → `MatchAll`: два товари з однаковими сумою/кількістю й різними зіставленими розмірами. Російські назви лишали неоднозначність; українські дають правильні ймовірні зв’язки «сума й товари». Новий однаковий конкурент знову скасовує унікальність.
- Старий кеш результатів із російськими назвами не перевикористовується після оновлення назв: fingerprint включає поля позицій. Серіалізація/перезапуск зберігає українські назви й результати; придатні деталі Checkbox залишаються.
- Окремий Windows/STA-сценарій: parser → оновлення автоприв’язок → workspace → обидві таблиці → перезапуск із серіалізованого кешу без повторних запитів деталей. Немає змін галочок, ручних записів, історії друку або викликів принтера.

## Реальна read-only перевірка

Для двох наданих користувачем замовлень виконано два GET деталей із локальним DPAPI-токеном лише в пам’яті: HTTP 200, українське поле присутнє в усіх **7 із 7** позицій. Після виправлення виконано ще два GET через зібраний `PromOrdersClient`: результат для наведених користувачем USB-розетки й LED-підсвітки український. Payload замовлень, секрети, покупці та реальні ідентифікатори в Git не додаються.

Це перевірка отримання назв, **не підтвердження конкретних живих прив’язок**. Живі дані Checkbox у цьому запиті не читалися; фізичного друку чи фіскальних операцій не було. API та профілі користувача не змінювалися.
