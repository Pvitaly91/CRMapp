# Усі накладні — 09.10.2026

Версія 1.0.30 додає третю вкладку основного вікна. `WaybillService` залежить лише від захищених налаштувань доставки й HTTP-транспорту: замовлення маркетплейсів, Checkbox, автоматичні й ручні зв’язки не є джерелом накладних або умовою доступності.

Нова пошта читається через існуючий `InternetDocument/getDocumentList`: усі збережені акаунти, періоди до семи днів, сторінки до збігу кількості унікальних документів із числовим `info.totalCount`, перевіреним у реальній відповіді API. За відсутності цього лічильника завершення підтверджує порожня сторінка. Для нового списку межа сторінок розширена до 1000; старий діагностичний пошук ТТН зберігає власні десять сторінок. Повторена сторінка, перевищення межі, суперечливий лічильник або неповна відповідь позначають джерело неповним, а не успішно завантаженим. Документи різних акаунтів мають окрему ідентичність; однакові збережені ключі не спричиняють повторного сканування акаунта.

Rozetka Delivery читається через незалежний `GET /api/track` із Bearer, обома `partner_type` та чотирма комбінаціями `is_archived/is_deleted`. Перевіряються `pagination.page/limit/page_count/total_count` і повтори документів. Застосовується контракт [офіційної OpenAPI](https://rz-delivery.rozetka.ua/api/docs/swagger-ui-init.js), також доступний через [Swagger UI](https://rz-delivery.rozetka.ua/api/docs/). [Офіційна інтеграція Нової пошти](https://novaposhta.ua/en/for-business/cooperation/integration/) підтверджує JSON endpoint; сторінка конкретного методу під час перевірки повертала Cloudflare 403, тому необов’язкові поля НП не позначені новим офіційно підтвердженим контрактом. Наявний механізм читання та обмежений whitelist записів збережено.

Відсутність ключів і помилки акаунтів показуються окремо. У таблиці залишаються успішно прочитані джерела й явно позначені часткові результати. Ключі, токени, повні відповіді API та адреси HTTP-запитів не виводяться в діагностичних повідомленнях. Зміна періоду, налаштувань або скасування знецінює стару операцію; пізня відповідь не може підмішати документи іншого періоду чи акаунта.

Дата, пошук і фільтр перевізника працюють окремо від фільтрів чеків і замовлень. Кнопки друку чеків приховані, команди друку й перегляду чеків не активні. Клітинки копіюються через загальний механізм Ctrl+C та контекстного меню.

Перевірки охоплюють пагінацію НП понад десять сторінок, діапазони дат, акаунти, чотири стани Rozetka Delivery, помилки одного джерела, некоректні або повторені сторінки, скасування, застарілі відповіді, сортування й копіювання у скомпільованому XAML. Реальний друк під час перевірок не виконується.

Окрема перевірка лише читання реального API за 09.10.2026 завершила завантаження 16 накладних НП (`Complete=True`); захищений файл налаштувань залишився побайтно незмінним. У локальному профілі немає токена Rozetka Delivery, тому його живий запит не запускався. RD перевірено за офіційною OpenAPI й синтетичними HTTP-відповідями.

Повний набір: 397/397 тестів, exit code 0. Скомпільована вкладка візуально перевірена на синтетичних накладних обох перевізників; помилок прив’язок XAML немає.
