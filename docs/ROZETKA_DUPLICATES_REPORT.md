# Повторні замовлення Rozetka — 1.0.41

У робочій конфігурації були два ввімкнені підключення з однаковими збереженими логіном і паролем Rozetka. Обидва завантажували той самий магазин. Раніше `MarketplaceOrderDeduplication` об’єднував тільки Prom за токеном, тому Rozetka залишав два рядки одного замовлення.

Тепер однакові повні облікові дані Rozetka доводять еквівалентність підключень у межах поточного сеансу. Логін обрізається по краях, як у запиті авторизації; регістр логіна і пароль порівнюються точно. Неповні, недоступні або різні дані не об’єднують акаунти. Назви магазинів і номери замовлень самі по собі не доводять еквівалентність. Правило Prom за токеном збережено; ідентичності обмежені маркетплейсом.

Канонічний ID вибирається стабільно за порядком ID підключень. Кеш, підключення, захищені секрети та збережені ручні рішення не переписуються. Їхні ключі нормалізуються лише для представлення і зіставлення, тому після зміни облікових даних початкові ключі знову доступні. Вибір наклейок із дублів переноситься до єдиного рядка. Історія наклейок відновлюється за перевізником і ТТН. Найновіші поля замовлення беруться з останньої завантаженої версії, а всі фіскальні твердження, включно із суперечливими, зберігаються.

Додано 8 регресій: кеш/F5/перезапуск із ручною прив’язкою, автоматичний збіг і відхилення alias, розділення та повторне об’єднання після зміни пароля з перенесенням галочки, повні й доступні credentials, межі акаунтів і Prom, фіскальні суперечності, незмінність збережених рішень, історія друку та вибір кандидатів. Скомпільований XAML перевірено з одним рядком Rozetka і натисканням справжньої кнопки кандидатів. Повний набір: **483/483**. Нові сценарії використовують вигадані дані й підмінені сервіси без справжнього API та фізичного друку.

Синхронізація й надалі читає всі ввімкнені підключення; ця зміна усуває дублювання рядків і джерел сповіщень та не видаляє підключення користувача.
