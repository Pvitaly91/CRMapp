# Єдине оновлення — 1.0.38

Кнопка «Оновити все» у верхній панелі та F5 запускають один цикл для вибраного періоду: чеки Checkbox → замовлення та перевірка автоприв’язок → накладні Нової пошти й Rozetka Delivery. Кнопка доступна на всіх вкладках. Прибрані окремі кнопки «Оновити чеки», «Оновити замовлення», «Оновити автоприв’язки» та «Оновити накладні».

Повторні виклики поділяють поточний цикл. Загальний стан зайнятості залишається встановленим між фазами; перегляд, друк і зміна налаштувань не починаються до завершення. Якщо вже йде друк чеків або наклейок, цикл не запускається. Загальне скасування доступне у верхній панелі під час роботи.

Дати перевіряються до мережевих запитів і фіксуються для циклу. Зміна дат або завершення роботи програми скасовує його. Перехід між вкладками не скасовує явно запущене оновлення накладних. Автоматичні запити від вкладок і таймера не дублюють спільне оновлення.

Маркетплейси перевіряють вибраний період і після помилки Checkbox. Відсутній ключ або збій одного сервісу не зупиняє решту; докладний стан служб показаний у підказці кнопки. Завершення циклу не означає успішної відповіді кожного API. Окремий внутрішній шлях оновлення чеків збережений для ініціалізації, дат і фонової синхронізації.

Після невдалого оновлення Checkbox попередній список чеків не підтверджує свіжість даних для нових автоприв’язок. Нові ймовірні пари та читання кошиків чекають успішної відповіді Checkbox; підтверджені й перевірені кешовані зв’язки зберігаються. Фоновий запит іншого періоду під час циклу відкладається, щоб його успіх не підтвердив застарілий список вибраного періоду.

Перевірки використовують синтетичні сервіси й принтер: усі вкладки, оновлення прив’язок при неактивній таблиці замовлень, відсутні облікові дані, незалежні помилки API, новий період після помилки Checkbox, повторні натискання, відкладення фонового запиту іншого періоду, зміна дат, вихід із вкладки накладних, блокування під час передачі друку й відновлення прив’язок після успішного повтору. Перевірка справжнього скомпільованого XAML перевіряє єдину кнопку та відсутність трьох позначених кнопок. Фізичний друк у перевірках не виконується.
